# Domain docs

This repository uses a single-context domain documentation layout.

## Before exploring domain behavior

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- Proceed silently when either location is absent; domain-modeling creates documentation when decisions are resolved.

Use terminology defined in `CONTEXT.md` in issues, specifications, tests, and implementation. Surface any conflict with an existing ADR explicitly instead of silently overriding it.
